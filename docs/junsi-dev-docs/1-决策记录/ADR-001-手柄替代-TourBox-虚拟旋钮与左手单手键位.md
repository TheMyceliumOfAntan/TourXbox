# ADR-001：手柄替代 TourBox：虚拟旋钮与左手单手键位

| 属性 | 内容 |
|---|---|
| 状态 | 已采纳 |
| 日期 | 2026-11-03 |
| 决策者 | AI Agent |

## 背景

TourBox 类绘图控制器价格高，用户已有 Xbox 手柄。手柄是模拟量输入，直接把摇杆当方向键无法调画笔大小；且画图时右手持笔，只有左手能操作放在桌面上、左手覆于其上的手柄正面按键，扳机键（背面）不可达。

## 决策

1) 自研 Windows 常驻工具 TourXbox（WinUI 3 + .NET 8，WindowsPackageType=None 免安装自包含），XInput 4ms 轮询，SendInput 注入键盘/鼠标。
2) 核心 KnobEmulator：摇杆偏移 → 死区(0.16) → 重标定 → tick/s = Max × t^Curve(1.8) → 累加器出档；轻推约 3 档/秒，推满约 13 档/秒；换向立即清空累加器防抖。
3) 轴锁定：斜推时只响应偏移更大的轴，切换主导轴需超出 1.35 倍（滞回），避免画笔大小与缩放互相误触。
4) 键位：左摇杆 ←→ 画笔大小、↑↓ 缩放；十字键 ←→ 笔刷预设、↑↓ 图层；View/Menu 撤销/重做；ABXY 画笔/橡皮/吸管/新建图层；右摇杆平移（Space+左键拖拽）；LB 层 = 左摇杆打圈旋转画布（角度→鼠标位移 1:1）；RB 层 = 右摇杆大小粗调/硬度；L3 按住 = 左摇杆平移；RT 留空自定义。
5) 仅当另一个前台进程匹配绘图软件时注入，绝不向自身窗口注入；暂停入口：托盘菜单、界面按钮、全局热键（Ctrl+Alt+P 被占用时自动回退到 Ctrl+Shift+Alt+P / Ctrl+Alt+F10）。
6) 配置为热重载 JSON（%APPDATA%\TourXbox\profiles），内置预设随程序发布并在首次运行复制到用户目录。

## 备选方案

### 方案 AntiMicroX / JoyToKey
- 优点：免费开源、现成可用
- 缺点：摇杆只能当方向键，没有档位手感；无分层、无按进程自动切换、无 OSD
- 为何不选：无法满足画笔大小微调的核心需求，故自研

### 方案 Interception 内核驱动注入
- 优点：可绕过 RawInput、对游戏也有效
- 缺点：需安装内核驱动，易被安全软件拦截，维护成本高
- 为何不选：绘图软件只吃普通键盘事件，SendInput 足够

### 方案 把旋钮映射到鼠标滚轮而非按键
- 优点：无需各软件快捷键配合
- 缺点：大多数绘图软件的滚轮是缩放/滚动，不是画笔大小
- 为何不选：仍需要按键注入才能精确控制参数

## 影响
- 新增 Core/Input、Core/Engine、Core/Actions 三层，UI 仅通过 MappingService 事件订阅，不直接触碰注入逻辑
- 引入 WindowsPackageType=None，弃用 MSIX 打包项目（保留文件但不参与解决方案构建），以支持开机自启与按需提权
- 热键注册失败必须降级而非静默失效，已写入 %APPDATA%\TourXbox\app.log
